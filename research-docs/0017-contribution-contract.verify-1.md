## Facts that several recommendations rest on

**F1. A rule's callback runs before its children are planned, and `Mapped` is lazy.** `planner.bind` (`contracts/generation/go/planning.go:519-566`) runs `Input.Capture` (`:522`), then `Expand` (`:548`), revokes the request (`:549-552`), and only then calls `p.resolve(expression, captures, f, depth+1)` (`:560`). `resolve` plans a child when it meets its placeholder: `case CapturedExpression: ... return p.use(use, f, depth+1)` (`:580-585`). `Expansion.Mapped` only records and returns a placeholder: "Mapped captures a use for the planner to represent after the callback" (`description.go:133`), `s.captures[slot] = use; return Mapped[T] (slot), nil` (`:169-170`). SPI:92: "Mapped records a dependency. It does not execute another mapping." A captured child whose placeholder the rule drops is admitted but never planned (SPI:162: "Only demanded native actuals need mappings").

**F2. What a callback can observe of a child.** The kernel's handle `Use[F]` and whatever the source reader says about it. `declarations.go:48-55` reads the body's *source* form: `body, descriptor, err := src.Descriptor(open.Body)` ... `if descriptor && body.Constructor == "record" { form = record }`. It cannot see what was *selected* for the child. The document's sentence "a callback never sees what was selected for a child" is TRUE.

**F3. Recursion is refused today; a reservation exists.** `planning.go:322-325`: `if p.active[id] { return 0, fmt.Errorf("%w: recursive native declaration", ErrUnsupported) }`. The same for a helper (`:686-688`). The ID is reserved before the recipe runs (`reserve()` at `:366`, `Expand` at `:373`), and the convention and a preliminary description are stored before the body is resolved (`:408-410`). SPI:391: "Recursion is explicitly unsupported by the current native construction profiles." `docs/generation-planner.md:313`: "The current profile rejects cyclic declaration dependencies." Recursion is a later family (RF:204-224, #164).

**F4. No "need more, then continue" shape exists in bittype's kernel packages.** A search of `contracts`, `engine`, `transform/syntax/shared`, `check/syntax/shared` for a work queue, pending, resume, continuation or demand handling finds only `planning.go:279` ("Representation stays demand-driven; admission is not"). The planner is one recursive descent with two memos (declarations per entity, admission per occurrence). The semantic kernel uses the opposite idiom, *declare up front, admit, then run once*: `contracts/semantic/go/evidence.go:12`: "EvidenceRequirement is a consumer-owned compatibility requirement, not a request to run a provider"; `:43-44`: "It never invokes a resolver or analyzer"; `request.go:37`: "No accessor fetches dependencies or resolves names"; TGP:535: "Neither the shared host nor a plugin invokes analysis on demand." The nearest existing shape to a staged protocol is the pair `Pattern.Capture` then `Expand`: two callbacks of one selected rule, the first of which names child uses for declared slots. Both run before any child is planned.

**F5. The generation contract's error values, and how a rule declines.** `contracts.go:13-22`: `ErrInvalid`, `ErrUnsupported`, `ErrScope`, `ErrLimit`, `ErrIncomplete`, `ErrAmbiguous`, `ErrRejected`. From `contracts/semantic/go`: `ErrEvidenceUnavailable` (verdict `Undetermined`, `source.go:187-188`). Wrappers: `SiteError` (`source.go:150-162`), `explanation` (`:164-170`), `errNotChild`, `errNotBody` (`description.go:187-190`). A source judgment has four verdicts, `Admitted`, `Unsupported`, `Rejected`, `Undetermined` (`source.go:83-92`), and "a diagnostic cannot add an error class: only the verdict classifies" (`:94-96`). A rule declines by returning any error from `Capture` or `Expand`; the planner passes it through unclassified (`planning.go:378-380`, `:523-525`, `:553-555`). The refusals that exist in the 21 packages: `src.Unsupported(use.Use, "nested records require a named declaration in this profile")` in the four record rules (Go `record.go:50`), `src.Unsupported(open.Body, err.Error())` in the common recipe (`declarations.go:43`), and the raw `fmt.Errorf("unsupported identifier %q", name)` of `naming.Exported` returned as is (Go `record.go:62-65`). `reader.Unsupported` returns `&text.Diagnostic{Code: text.Unsupported, ...}` (`transform/syntax/horos/source/go/read.go:126-133`), and `text.Diagnostic` has no `Unwrap` (`contracts/text/go`, only `Error()`); the registry returns such an error unchanged (`transform/syntax/shared/generation/go/diagnostics.go:12-15`). **By reading, a rule's refusal today matches none of the seven generation values.** No test names the "nested records" message.

## R3. One decision record with a staged planning protocol

1. **Premises.**
   - "The current sketch returns the final decision record and only then resolves its slots": TRUE of the sketch (submitted 6.5) and of the code (F1).
   - "A bounded work queue can drive it": PARTLY. Nothing like it exists (F4). The planner is recursive descent; a queue is new machinery.
   - "Reserve references before filling recursive bodies": the reservation exists, the recursive reference is refused (F3).
2. **Drift.** None on `main`. #281 changes `reserve` to take a role and provenance and adds `carry`; it does not change the order of F1.
3. **Conflicts.**
   - SPI:58-59, "Capture and Expand run only during planning. They do not recursively invoke the planner": kept, since the kernel drives the stages.
   - The implemented property F2 changes on purpose. Its accepted reason is F9, which the expert never saw and did not address. A staged protocol in which a decision reads evidence about an operand is compatible with F9 only if evidence about a *binder-bound* operand is never taken from one application (see R7, R8). The expert reaches a compatible position in R21 without the law.
   - TGP:535 ("Neither the shared host nor a plugin invokes analysis on demand"): `Need(typed demands)` must be limited to (a) represent a child use or a source-issued subject and (b) evidence from the selected dependency. It must not become a way to run source analysis.
   - Research 0015 rows 2 and 35: R3 refines both; no contradiction.
4. **Derivation.** The stage *order* is required by a concrete case. Which case:
   - None of the six delivered families needs evidence about a selected operand to produce today's output. Text and booleans are constants (`text.go`: `Output: model.Primitive(targetName)`); list is a template with one slot; record reads source fields and a source flag (`record.go:61-75`); Go's optional helper is valid for every `T`; the declaration recipe reads the source.
   - One delivered rule has the dependency latently: F10. It is the only place in the 21 packages where a decision is correct only if the operand's selection has a certain native form.
   - Accepted vertical cases 2 (`T | null` needs "The null representation cannot collide with a valid `T`", RF:248) and 5 (a map key requirement, RF:246) need it. They belong to #211 and #209.
   - The open `Advance → Need | Accept | Refuse` *loop* (more than one demand round) has no case I can name among the six families or the six cases: in each, the set of dependencies and evidence kinds follows from the source view alone.
   - **Smallest sufficient protocol:** keep two callbacks per selected rule, as today, and move the kernel's planning of the named dependencies between them: (1) declare, from the checked view and the reader: dependencies per slot and the evidence kinds wanted of each; (2) the kernel plans them and resolves the evidence; (3) decide, with the reader and typed answers, returns a decision record or a refusal; (4) freeze; (5) project, without the reader. That is `Advance` bounded to one `Need` before any answer. A second round becomes necessary only when *which* dependency is needed depends on an answer. One consequence to decide: today an unused capture is never planned (F1); with eager planning a declared but unused dependency can fail its parent.
   - **Can the first change carry the shape with only the no-demand path exercised?** Technically yes: all 21 packages would declare children and no evidence. It would not be a demonstrated final shape. `platform/docs/concepts/architectural-correctness.md` AC-07: "do not use one kind of evidence to claim another guarantee"; AC-08: the rule does not "justify speculative frameworks"; AC-10 requires "its inputs ... have their intended shape", and the typed answers are an input of decide. So the answers must be in the signature from the first change, and the evidence path needs a real consumer before the contract is called final: a fixture family with a requirement on its operand (the expert's own strong P2 case, R31), and F10 as a production consumer among the delivered rules.
5. **Changes.** `BindingDescription` (`Input`, `Output`, `Expand`), `Pattern`, `Capture`, `Expansion` (`Reader`, `Use`, `Mapped`), `DeclarationRecipe`, `DeclarationRequest`, `DeclarationDescription`; planner `bind`, `resolve`, `declare`, `use`; `Step`; `FreezeDescription`. Registry `plan`. All 21 packages, the common `declarations` and `pattern` packages, the independent fixture `integration/go/testdata/generationfixture`. The order and the answers input must be in the one change. Evidence kinds follow additively.
6. **Verdict: NEEDS ADAPTATION.** Adopt the five stages with one demand round and no general loop until a named case needs a second round; put typed answers into decide from the start; exercise the evidence path before finality (fixture, and F10); state F9 as a rule of the protocol; keep recursion refused in the first change (R9).
7. **Validation.** (a) A fixture nullable-like family whose decide receives the operand's evidence and records `direct` or `wrapped`: not expressible today (F2). (b) F10: register a record replacement whose native form is not the target's record form; today planning fails with `ErrInvalid` from `CheckDeclaration`; after delivery the declaration policy either selects the alias form from evidence or refuses with "requirement unsatisfied" naming the dependency.

## R4. The projector is registered on the contribution and gets no source reader

1. **Premises.** "Do not return a fresh projector closure from each decision call": the sketch never proposed one ("A contribution states ... a decide function and a projection", submitted 6.5), so this is a guard, not a correction. Today no rule returns a closure: a rule's result is `Expression[T]`, plain data (`expression.go:64-74`). The rule itself is one closure registered at `Describe` and it takes the reader inside the callback, Go `record.go:40-41`: `Expand: func(ctx context.Context, r g.Expansion[h.Language, s.Language, source.Reader]) (g.Expression[s.Language], error) { src, err := r.Reader()`. The request is revoked after the callback (`description.go:101-111`); the reader value `R` itself is not revocable by the kernel.
2. **Drift.** None.
3. **Conflicts.** None. Precedents for "no source reader" as an interface property: `contracts.go:33-34` "Build receives only the closed native program; it has no source reader, selectors or mapping callbacks"; `planning.go:38-39`; `freeze.go:10-11` "Owner callbacks must capture stable configuration".
4. **Derivation.** Not a new abstraction; a split of today's one callback.
5. **What it forbids that a rule does today.** In one callback Go's record rule reads `src.Descriptor(use.Use)` for the record's origin, `src.Fields(use)` for names, flags, origins and field uses, applies `naming.Exported`, decides the wrap and builds the form with `g.At(model.Field(f.Name, f.Optional, ty), f.Origin)` (`record.go:52-75`). Under R4 everything the native form needs must be in the decision record or in the kernel's views: member names, order, presence strategy, **and the diagnostic sites** (`f.Origin`, `view.Origin`), which RF places in the envelope ("Diagnostic provenance") and in the payload ("Family-specific diagnostic detail"). The common recipe likewise: name, form, parameter names and `RequiredUse` come from the reader today (`declarations.go:37-69`). Enforceable by signature: a projector type with the parameter `T` only, as `HelperRecipe[T]` and `Target[T]` have. Go cannot stop a contribution from passing state through its own package variables; that stays the trusted-contribution limit already recorded (SPI:369-372, TGP:487).
6. **Verdict: HOLDS.** Adjustment to record: the projector must receive origins through the record or the views.
7. **Validation.** A compile-level check in `integration/go` that the projector's function type mentions neither `F` nor `R`; and a mutant projector that needs a field name absent from the record cannot be written against the public type.
