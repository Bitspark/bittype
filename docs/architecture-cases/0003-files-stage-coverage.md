# bittype/ACX-003 — Files stage coverage assumed Horos was the only implementation

**Corrected, 7 November 2026.** Bittype's shared Files stage coverage test accepted any discovered Horos parser or formatter directory and rejected every other language. It claimed that the new TypeScript formatter lacked a documented fixture even though the executable placement test compiled both generated layouts. The test used language identity to decide a question about evidence. [Original test](https://github.com/Bitspark/bittype/blob/494f3847c8bdf3ef2751ab1ed927e06b261475b5/integration/go/architecture_test.go#L303) · [Files and Source](../source.md)

**AC-03 and AC-06.** The first implementation's scope became a restriction in the shared test. A second Files formatter through the same public contract required editing that restriction. The invariant the test needed was that every implemented stage has a corresponding conformance fixture. Parser and formatter coverage can vary independently. [AC-03](https://github.com/Bitspark/platform/blob/main/docs/concepts/architectural-correctness.md#ac-03) · [AC-06](https://github.com/Bitspark/platform/blob/main/docs/concepts/architectural-correctness.md#ac-06)

**Correction.** The shared test now compares discovered stage packages with the integration suite's supplied fixtures. The test composition associates each concrete Go provider package with the test that exercises it. A new provider adds its implementation, test and association. The checker rejects missing fixtures and associations with absent stages. [Coverage check](../../integration/go/architecture_test.go) · [Test composition](../../integration/go/files_stage_cases_test.go)

**Qualification.** Horos contributes a Files parser and formatter. TypeScript contributes a Files formatter with a distinct module and import policy. Their tests exercise those behaviors through the public contracts. The coverage check establishes that an association exists. The individual tests establish what the provider does.
